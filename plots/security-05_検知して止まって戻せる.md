## ねらい

S3最終話・アークの決着。深夜のGuardDutyアラート→隔離→逆探知のリアルタイム封じ込め。青柳の主役回として、採用面接の言葉「検知して、止まって、戻せる仕組みを作る側になりたい」(S1-01)を2年越しに回収する。侵入者は捕まらないが、「叩かれ続ける前提で設計し、説明できる」状態で季節を閉じる。瀬名の父入院の前震(S8への正典伏線)。

## ビート

1. **冒頭ログ断片**: GuardDutyの検出記録1行(深夜2時台)。
2. **起**: 導入して2週間のamazon_guarddutyが深夜に鳴る——旧東雲系リソースからの異常なAPI列。オンコールは青柳。数秒の躊躇もなく、インシデント宣言と美咲・風間への同報(S1-05の20分、S1-07の数秒、の系譜の完成形)。夜間の初動は青柳が一人で正しく打つ——隔離用SGへの付替え、ロールの一時停止。
3. **承(封じ込めと逆探知)**: 朝、amazon_detectiveで時系列を遡行——起点はS3-04で交換済みの旧鍵の再試行(失敗の山)と、残っていた低権限の口。実害なし。ただし攻撃者の正体は特定できず、以後も低強度の試行は続く(現実路線)。「捕まえる」ではなく「叩かれても倒れない・気づける・説明できる」を勝利条件として明文化。
4. **転1(検知の網を常設に)**: amazon_inspector(EC2/コンテナの脆弱性を継続スキャン——古い東雲AMIから既知脆弱性を検出し棚卸し)、amazon_macie(S3の機密データ自動発見——「平文の個人情報がどのバケットに」を機械が数える。③の在庫検分の常設化)、aws_security_hub(全部の検知を一枚の台帳に集約。基準チェック)。「単品の警報から、台帳のある防犯へ」。
5. **転2(検問の常設とガバナンス)**: S2-06で予告した「三階」——aws_network_firewall(VPC内の検問所。ドメイン/シグネチャベースの制御)を隔離OUと本番の境界に配備。aws_firewall_manager(Organizations全体へWAF/SG/Network Firewallのルールを一括適用——「野良アカウントにも塀と検問を強制」)。aws_shield/aws_waf はサービス総称としてコラム担当(本文はS2-06の実績の再掲参照)。監査対応はaws_artifact(AWSの適合性レポート取得=共有責任の相手側の証明)とaws_audit_manager(証拠収集の自動化)——狩野・風間の「監査に書ける」の道具として。
6. **結(季節の締め)**: 事後レビューで青柳が報告書を書き切る。美咲が面接の日の面接票の話を初めて本人にする——「丸を三つ付けた。作る側に、なったね」。風間が東京へ戻る前に総括「止める、の次に、説明できる、まで来ました。この季節の宿題は完了です」。——そして散会後、瀬名のスマホに東京の病院からの着信。今度は、出る。短い通話。「……親父が、入院した」とだけ美咲に告げ、詳細は語らない(S8「瀬名がいない日」への前震。説明しない)。締めは美咲の手帳——「名札と鍵束、完了。残る赤丸1つ。瀬名さんの引き継ぎ台帳(いつか)」——「いつか」に、まだ日付が書けない、という静かな不穏で閉じる。

## 対比

- GuardDuty(脅威検知)vs Inspector(脆弱性)vs Macie(機密データ発見)vs Detective(調査)——「いつ・何を・どう見る」の役割分担
- Security Hub(集約)vs 個別サービス
- Network Firewall(VPC内検問)vs WAF(L7)vs Shield(L3/L4)——S2-06の層の完成
- Firewall Manager(組織一括)vs 個別適用
