# 幕間 外から見える鍵穴 — IAM Access Analyzer

*SAA-C03 短編小説集 / S3幕間01 — 用語集外の頻出トピック補強(ショートショート)*

---

名札の棚卸しが終わった月の、次の滞在で、風間祐里は答え合わせから始めた。

「先月の台帳には、実は一つ穴があります。私たちは建物の中から数えました。名札が誰のものか、鍵束に何が入っているか。——外から見て、どの鍵穴が通りに面しているかは、まだ数えていません」

「外から、って」青柳凛が聞き返した。「攻撃者の視点ってことですか」

「そこまで物騒ではありません。正確には、このアカウントの外の誰かから届き得る資源を、機械に列挙させます。IAM Access Analyzer。信頼の内側をこのアカウントと決めて、その外から設定上手が届くもの——S3のバケット、KMSの鍵、ロール、全部です。実際に誰か来たかではなく、ポリシーを読んで『届き得るか』を判定します。私の目視より、こちらの方が確実です。私は疲れますが、これは疲れないので」

「公開バケットの検出と、何が違うんですか」と堂島美咲が訊いた。一年半前、風間からこの会社に届いた最初のメールが、まさに公開バケットの指摘だった。

「あのとき見ていたのは『世界中に開いているか』でした。これが見るのは『外の誰かと共有しているか』——公開まではしていないが、よそのアカウントに開いている、半開きの鍵穴まで含みます。半開きは目視ではまず落とすんです。当時の私は、週末を潰して手で数えていました」

「……手で、ですか」

「手で。数え間違いもしました。だから、機械に任せられるところは任せると決めたんです」

有効化は数分で終わった。初回の走査が返ってくる。検出、1件。

——外部プリンシパルからアクセス可能: IAMロール。

部屋の空気が、わずかに固くなった。深夜のサインイン試行の一覧が、全員の頭のどこかにまだ貼り付いている。名前を試している誰かが、もう中に手を掛けて——

「落ち着いてください」風間の声だけが平坦だった。「検出は疑いであって、有罪ではありません。仕分けるのが、人の仕事です」

辿ると、そのロールの貸出条件に書かれた外部アカウントは、狩野沙耶が今年の契約で結んだ監査法人のものだった。決算の時期に、先方の担当者がこちらの帳票の置き場を読みに来るための、正規の窓口。契約書の条番号を理由に書き添えて、想定内の共有としてアーカイブする。

「本物だったら、って思いました」青柳が息を吐いた。

「本物でも、手順は同じです。列挙して、仕分けて、説明できないものだけ潰す。……これでゼロ件。以後、誰かがポリシーを変えるたびに、これは黙って数え直します。私が東京にいる日も」

会議のあと、青柳は風間の席にコーヒーを置きに行って、開いたままのノートを、うっかり見た。先月の棚卸しの指摘が一行ずつ並び、横に正の字が刻まれている。そして消し込んだ項目の頭には——小さな花丸が付いていた。監査票のあの几帳面な字と、同じペンで。

「……花丸、付けるんですね」

風間はノートを閉じなかった。閉じないまま、少しだけ間を置いた。

「消し込みの快感で保っている仕事です、監査は」

それだけ言うと、検出ゼロの画面をスクリーンショットに撮り、印刷して、ノートの今日のページに貼った。

「ゼロの日は、貼っておくんです。またすぐ増えるので」

夕方の新幹線で風間は東京へ帰っていった。青柳は輪番チャンネルに今日の作業を三行で報告し、最後にもう一行足すかどうか少し迷って、やめた。花丸のことは、書かないでおくことにした。ゼロの画面を貼る人がこちら側にいる——それが分かっただけで、深夜のログの足音が、少しだけ遠くなった気がした。

## 補講コラム — IAM Access Analyzer

**信頼の内側(アカウントまたは組織)の外からアクセス可能なリソースを、ポリシーの解析で機械的に列挙する機能。外部アクセスの分析に追加料金はない。** 対象はS3バケット、IAMロール、KMSキー、SQSキュー、Lambda関数など。実際のアクセスの痕跡ではなく、リソースベースポリシー等を数理的に解析して「設定上、届き得るか」を判定する。

要点は三つ。①**「公開」の検出より範囲が広い**——インターネット公開だけでなく、特定の外部アカウントとの共有も列挙する。②有効化した後は、**ポリシーが変更されるたびに継続的に再評価**する(一回きりの棚卸しではなく監視)。③検出は「共有されている」という事実であって不正ではない——正規の共有は理由を付けてアーカイブし、説明できない検出だけを潰す。「アカウント外からアクセス可能なリソースを特定・継続監視したい」が要件語。データの中身(機密情報の有無)を見る装置ではない点も混同されやすい。

## 確認クイズ

1. 「組織のアカウント内で、外部のAWSアカウントやインターネットからアクセス可能なS3バケットとIAMロールを継続的に検出し、意図しない共有だけを是正したい」——何を使い、検出結果はどう運用するか?
   → IAM Access Analyzerを有効化する(信頼ゾーン=アカウントまたは組織)。ポリシー変更のたびに再評価されるため継続監視になる。検出は外部共有の列挙であり、監査法人向けロールのような正規の共有は理由を記録してアーカイブし、説明できない検出のみ修正する。
