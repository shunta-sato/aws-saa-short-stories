# 攻める者、迎える者 — WAF/API Gateway編

*SAA-C03 短編小説集 / S2-06 — networking_and_application_security*

---

門の取っ手を揺すっていた手は、秋になって、本気を出した。

保護者ログインへの総当たりが、複数のIPレンジに散って再開した。同時に、学校プランのページを機械的に舐めて回る収集も始まった。署名付きCookieの鍵は破られていない——中身は無事だ。だが、ログイン画面とAPIは殴られ続け、正規の保護者のレイテンシがじわじわ悪化していた。

「中身が無事でも、玄関で乱闘されたら営業妨害です」と青柳凛がログを睨む。「これ、うちの手に負える話ですか」

狩野沙耶の懸念は、もう一段深かった。「学校に『攻撃を受けています』と説明する事態は避けたい。でも、黙っていて後から知られる方が、もっとまずい。——現状を一枚で説明できる紙を、今週中に。それと、止める算段を」。守る話と説明する話が、また同時に来ている。

算段の答えの代わりに、月曜の朝、東京から人が降りてきた。新神戸の改札を抜けてきた風間祐里は、キャリーケースひとつで運用部屋に現れ、挨拶より先にホワイトボードのマーカーを取った。メールと監査票の人が、初めて現場に立った日だった。

「メールで往復する段階は過ぎたので、来ました。——最初に、守りの層を整理します。ここを混ぜると、道具選びを全部間違えるので」

風間は板書した。

「一階。L3/L4——ネットワークの洪水そのもの。SYNフラッドや反射攻撃。これは**AWS Shield**の領分です。Standardは、実は皆さん全員がもう持っています。全AWS利用者に自動で、無償で効いている。Advancedは有償で、年間コミットが要る代わりに、専門チーム——SRTの支援と、攻撃時のコスト増への保護が付く。二階。L7——リクエストの中身。総当たりも機械収集も、一つ一つは正規の形をしたHTTPです。洪水ではなく、悪意のある客。これが**AWS WAF**の領分。三階、VPCの中の通信の検問は、また別の道具ですが——それは次の季節の話」

「今日の相手は、二階ですね」と堂島美咲。

「二階です。**Web ACL**——ルールの束を作って、入り口に関連付けます。おたくの入り口はCloudFrontとALB。ひとつ注意——CloudFrontに付けるWeb ACLは、us-east-1で作る決まりです」

実装は速かった。まず**マネージドルールグループ**。OWASP系の定番の攻撃パターンを束ねた既製のルールで、自分たちでシグネチャを書かずに即日適用できる。「ただし、いきなりブロックにしない」と風間は釘を刺した。「まずカウントモードで流して、正規の通信を誤検知していないか数える。善意のブロックは、善意のNACLと同じくらい質が悪いので」

その言い方に、美咲は苦笑いするしかなかった。あの一件は、監査票のどこかに書かれているらしい。

次に、総当たり対策の本命——**レートベースルール**。時間窓の中で、同じ送信元からのリクエスト数がしきい値を超えたら、自動で遮断する。ログインのパスにだけ、厳しめのしきい値を張る。

「しきい値は現実と相談です」美咲が数字を決める側に回った。「厳しすぎると、正規の利用者を巻き込む。特に——うちが一番よく知ってますけど——学校や会社のネットワークは、NATの向こうに何百人もいて、全員が同じIPに見える。行事の夜、保護者200人が学校の回線から一斉に見に来たら、それは攻撃じゃなくて営業です」

カウントモードの観察は一週間続けた。案の定、木曜の夜に一件、引っかかった。ある保育園の発表会の夜、園の回線からのアクセスがしきい値の候補を超えたのだ。全部、正規の保護者だった。もしいきなりブロックにしていたら、発表会の夜に「見られない」の電話が鳴っていた。数字を一段緩め、ログインパス以外への適用をやめ、それからブロックに切り替えた。

「守りの数字を決めるのに、営業のカレンダーが要るんですね」と青柳がメモした。「行事の夜のピークが、しきい値の下限になる」

切り替えの翌朝、総当たりのグラフは429——Too Many Requestsの壁に当たって崩れ、機械収集はマネージドルールが刈った。正規の保護者のレイテンシが、元の平らさに戻る。狩野への「一枚の紙」には、攻撃の推移と対策と、そして誤検知ゼロの根拠——保育園の夜の一件——まで書けた。守った話と説明できる話が、今回は最初から一枚だった。

締めのレビューで、後ろの席の瀬名要が一言だけ言った。

「止められたな。——ただ、止めたことと、説明できることは、別だぞ。誰が来て、何を試して、うちは何を根拠に遮断したのか。それを問われる日が来る」

「ええ、来ます」風間は板書を消しながら、事もなげに答えた。「監査ログ、権限、鍵の管理——その話は、次の季節にまとめて。今日は門番を立てるところまでです」

---

門番が立つと、今度は「正しく迎える」側の案件が動き出した。春にPrivateLinkで繋いだ印刷パートナーとの取引が軌道に乗り、他の製本会社からも引き合いが来ている。閉域の一対一の窓口を、正式な商品としてのAPIに育てる番だった。狩野の要件は商売の言葉で明快だった。「取引先ごとに利用量の上限を約束したい。上限は契約の等級で変える。変な注文データは入り口で弾きたい。それから、さっき立てた門番——WAFも、この入り口に付けたい」

「全部、機能の名前に翻訳できます」美咲は指を折った。「上限の約束=使用量プランとAPIキー。等級=プランの段階。入り口で弾く=リクエスト検証。門番=WAF連携。——ここまで揃えて、玄関を選びます」

「APIの正式な玄関なら、**Amazon API Gateway**です。ただ、種類があるので要件で選びます」美咲は選定の階段を書いた。

「**REST API**。フル装備です。APIキーと使用量プランで取引先ごとのクォータとスロットリング、リクエストの形の検証、キャッシュ、そしてWAFの直結。狩野さんの要件は、全部この装備の名前です。——対抗馬の**HTTP API**は、軽くて安くて、JWT認可で自前のアプリの裏口にするなら最高なんですが、使用量プランもキャッシュもWAF直結もない。商品として売るAPIには、装備が足りません。今回は棄却」

「注文のステータスを、こっちから即時に通知してほしい、という要望も来てますけど」と青柳。

「それは通信の形が違う。頼まれて答えるんじゃなくて、こちらから押す——双方向なら**WebSocket API**。接続をIDで管理して、サーバー側から送りつけられる。注文APIとは別系統で、必要になったら建てます」

「電話と、伝言板の違いやな」と矢吹。「注文は伝言板に書いてもろたら返事する。せやけど『刷り上がりました』は、こっちから電話せなあかん」

対比のために、正反対の小さな口もひとつ作った。社内バッチの完了を叩くだけの簡易フックには、API Gatewayを立てるまでもない。**Lambda Function URL**——Lambda関数に直接生やせる最小のURLで、認証はAWS_IAMに絞る。「フル装備の玄関と、勝手口。玄関の機能が要らない内輪の口に、玄関の家賃を払わない」

入り口の場所も決めた。**エンドポイントタイプ**は三種類ある。世界中の利用者のためにCloudFront網で受けるエッジ最適化。特定リージョンで受けるリージョン型。VPCの中だけのプライベート型。「パートナーは国内固定なのでリージョン型。エッジ最適化は、うちはもう自前のCloudFrontを持ってるので、二重の売店になるだけ。社内の管理APIはプライベート型にして、VPCエンドポイント経由でしか呼べなくします」

最後のピースが、バックエンドへの接続だった。注文処理のECSは、プライベートサブネットの奥にいる。玄関から奥座敷まで、どう通すか。

「**VPCリンク**です。API Gatewayから、VPCの中へ入るための専用の橋。REST APIのVPCリンクはNLBが前提——ここ、PrivateLinkのときのNLB前提と同じ理屈です。玄関は表に、座敷は奥に、橋は一本だけ」

「プライベートAPIと混ぜたらあかんのやろ、それ」矢吹智弘が確認した。「向きが逆や、いう話やな」

「逆です。VPCリンクは『APIからVPCの中へ』入る橋。プライベートAPIは『VPCの中からAPIへ』行く門。行きと帰りを混ぜると、試験も設計も間違えます」

---

仕上げの検証で、青柳が新しい道具をひとつ覚えた。保護者アプリのログインフローがWAFと署名Cookieの導入で変わったため、多端末での動作確認が要る。会議机に私物の端末を並べかけた青柳に、美咲が**AWS Device Farm**を教えた。クラウド上の実機ファームで、自動テストも手動操作もできる。

回してみると、初日に一件、古いAndroidのブラウザ内蔵WebViewでCookieの扱いが違い、ログインがループする不具合が見つかった。行事の夜に保護者から問い合わせが来る前に、直せた。

「手元に端末を並べる時代やないんやなあ」矢吹がしみじみ言った。「うちのDCには、検証用の携帯が籠に山盛りあったで。充電ケーブルが絡まっとる籠が」

「その籠、フローログのREJECTみたいな顔で言わないでください」と青柳が返し、部屋が少し笑った。

---

秋の終わりの輪番で、美咲はこの半年の成果を一枚の絵にした。城の地図だ。

敷地と通り(VPC、サブネット、ルートテーブル)。門(IGW、NAT、エンドポイント)。閉じた道と橋(VPN、専用線、PrivateLink)。受付(ALB、NLB、GWLB)。案内板(Route 53)。世界中の売店と、その鍵(CloudFront、署名)。そして検問(WAF、Shield)。春に「送信元IPを即答できない」事務の一枚から始まった地図は、一枚で説明が終わるところまで描き込まれていた。

描き終えて気づいたことがある。この半年、火種はいつも前の応急処置から生まれた。放置した赤丸がメンテ通知になり、急造のNATが請求書になり、開いた世界が攻撃を連れてきた。後手の連鎖だった。ただ、途中から、少しずつ先手が混ざった。赤丸が付く前のバックアップ回線。行事カレンダー先回りの受付。保育園の夜を先に数えたしきい値。地図というのは、たぶんそのためにある。どこで転んだかを覚えておく紙ではなく、次にどこで転ばないかを決める紙だ。

輪番の名物になった赤ペンは、この日、一度も使われなかった。残っている赤丸は、東雲由来のバッチサーバー1台——日付と持ち主の書かれた、あの一つだけだった。

「地図はできた」瀬名がそれを眺めて言った。「だが、地図に描いてないものがある。——この城の、どの部屋に、誰が、どの鍵で入れるのか。名札と鍵束の話が、丸ごと残ってる」

「IAM、KMS、監査」風間が頷いた。「止めたことと説明できることは別、の続きです」

翌朝、美咲は新神戸まで風間を送った。ホームで新幹線を待つ間、風間はキャリーケースの持ち手に手を置いたまま、ふと言った。

「一年半前、公開バケットの指摘メールを送ったとき——正直、返事は期待していませんでした。『いつか』で終わる会社が、ほとんどなので」風間は入線してくる車両に目をやった。「おたくは、全部に日付を付けた。だから次の季節は、私の番ですね。東京から、もう少し頻繁に来ます」

「歓迎します。……正直に言うと、少し身構えてもいます。風間さんの監査は、細かいので」

「細かいですよ」風間は否定しなかった。「でも、通り道を半年でここまで描けたチームなら、名札と鍵束も描けます。地図の描き方は、もう知っているんだから」

新幹線が風間を乗せて出ていくと、ホームには秋の風が残った。美咲は手帳を開き、次のページの一行目に書いた。「名札と鍵束」。城の地図の余白は、まだ広い。

## 用語コラム — この章の登場用語と決め手

### waf_web_acl(AWS WAF Web ACL)

**L7=リクエストの中身を検査するルールの束。CloudFront・ALB・API Gateway等に関連付ける。** 「SQLインジェクション」「不正なボット」「特定パターンの遮断」が要件語。CloudFrontに付けるWeb ACLはus-east-1で作成する、という配置の細部が定番の問われどころ。L3/L4の洪水はShieldの領分——層の区別が第一歩。

### waf_managed_rule_group(WAFマネージドルールグループ)

**OWASP系など定番の攻撃パターンを束ねた既製ルール。自分でシグネチャを書かずに即日適用。** いきなりブロックせず、まずカウントモードで誤検知を数えてから切り替えるのが定石——「善意のブロックは善意のNACLと同じくらい質が悪い」。「専門知識なしで一般的な脅威から保護」が要件語。

### waf_rate_based_rule(WAFレートベースルール)

**時間窓内のリクエスト数がしきい値を超えた送信元を自動遮断。** 総当たりやスクレイピングへの本命で、超過には429を返す。注意はNAT配下の巻き込み——学校や企業の回線は数百人が同一IPに見えるため、しきい値は正規のピーク(行事の夜)と相談して決める。「ブルートフォース」「過剰なリクエスト」が要件語。

### shield_standard_advanced(AWS Shield Standard / Advanced)

**L3/L4のDDoSからの保護。Standardは全利用者に自動・無償で有効。** Advancedは有償(年間コミット)で、SRT(Shield Response Team)の支援、攻撃時のスケールによるコスト増への保護、高度な検知が付く。「追加費用なしのDDoS対策」=Standard、「専門チームの支援・コスト保護」=Advanced、で判別。リクエストの中身の検査はWAFの仕事。

### amazon_api_gateway(Amazon API Gateway)

**APIの正式な玄関。認可・スロットリング・検証・監視を入り口で束ねる。** REST/HTTP/WebSocketの3形態と、エンドポイントタイプ、VPCリンクまで含めて「どの玄関を、どこに建てるか」で設計する。バックエンド(Lambda/ECS等)に入り口の雑務を持ち込まないための層。

### api_gateway_rest_api(REST API)

**フル装備の玄関。APIキー+使用量プラン、リクエスト検証、キャッシュ、WAF直結。** 「取引先ごとのクォータ」「商品としてのAPI公開」が要件語。装備が要らないならHTTP APIの方が安い——要件の装備名(使用量プラン等)が出たらREST、と覚える。

### api_gateway_http_api(HTTP API)

**軽量・低価格・低レイテンシの玄関。JWT認可とプロキシ統合が得意。** 自社アプリの裏口APIには最適だが、使用量プラン・キャッシュ・WAF直結がない——この欠落がそのまま棄却理由になる。「コスト最優先のシンプルなAPI」ならこちらが正答側に回る。

### api_gateway_websocket_api(WebSocket API)

**双方向の玄関。サーバー側から押して通知できる。** 接続をIDで管理し、チャット・リアルタイム通知・注文ステータス配信などに使う。「クライアントへのプッシュ」「双方向」が要件語で、REST/HTTPの応答型とは通信の形が違う別系統。

### api_gateway_endpoint_types(API Gatewayエンドポイントタイプ)

**エッジ最適化(CloudFront網で受ける)/リージョン(特定リージョンで受ける)/プライベート(VPC内のみ)。** 自前のCloudFrontを既に持つならエッジ最適化は二重になるためリージョン型+自前CDN、が実務の定石。社内専用APIはプライベート型+VPCエンドポイント。「利用者がどこにいるか」で選ぶ。

### api_gateway_vpc_link(API Gateway VPCリンク)

**API Gatewayから、VPC内のプライベートなバックエンドへ入る専用の橋。** REST APIのVPCリンクはNLB前提(PrivateLinkと同じ理屈)。プライベートAPI(VPCの中からAPIへ行く門)とは向きが逆——「APIから中へ」がVPCリンク、「中からAPIへ」がプライベート型、の混同が定番のひっかけ。

### lambda_function_url(Lambda Function URL)

**Lambda関数に直接生やせる最小のURL。玄関の家賃が要らない勝手口。** 認証はAWS_IAMかNONEの二択で、使用量プランもキャッシュもない。「API Gatewayの機能が不要な、単機能の簡易エンドポイント」が要件語。フル機能が要るならAPI Gatewayへ——要件の装備で分岐する。

### aws_device_farm(AWS Device Farm)

**クラウド上の実機ファームで、モバイル・ブラウザの自動/手動テストを回す。** 多端末互換の検証に、手元に端末の籠を持たなくてよい。「多様な実機での検証」「特定端末でのみ起きる不具合の再現」が要件語。本章では古いWebViewのCookie不具合を行事前に1件検出した。

## 確認クイズ

1. ログインページへの総当たり攻撃を緩和したい。ただし学校の共有回線(NAT配下の数百人)を誤って遮断したくない。使う機能と運用上の注意は?
   → WAFのレートベースルールをログインパスに適用し、時間窓内のしきい値超過を遮断(429)する。NAT配下では多数の正規利用者が同一送信元IPに見えるため、しきい値は正規ピーク(行事の夜など)の実測と相談して設定し、まずカウントモードで誤検知を確認してからブロックに切り替える。

2. 取引先ごとに利用量の上限(クォータ)を設け、WAFも直結したい商用API。REST APIとHTTP APIのどちらか? 理由は?
   → REST API。APIキー+使用量プラン、リクエスト検証、キャッシュ、WAF直結を備える。HTTP APIは軽量・低価格だが使用量プラン・キャッシュ・WAF直結がなく、商品としてのAPI公開の要件を満たせない。

3. API Gatewayからプライベートサブネット内のバックエンドへ接続する仕組みと、「VPC内からのみ呼べるAPI」の違いは?
   → 前者はVPCリンク(REST APIではNLB前提)で、API Gatewayから中へ入る橋。後者はプライベートエンドポイントタイプのAPI+VPCエンドポイントで、VPCの中からAPIへ行く門。方向が逆であり、混同させる選択肢が定番。

次の話: S3-01(セキュリティ/ID編・執筆予定)
