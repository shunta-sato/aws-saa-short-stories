# 短編4: データセンターを畳む日 — ハイブリッド編

*SAA-C03 短編小説集 / storage_architecture (4/5)*

---

ファイルサーバーを片付けた翌週、瀬名美咲は東雲アーカイブズ社の地下フロアに戻ってきた。矢吹が「また来週、頭を抱えよう」と言い残した三つの宿題が、まだ手つかずで残っている。

「整理するぞ」と堂島がホワイトボードに書いた。「残る課題は三つだ。①地下の奥にある三十年分のテープライブラリ。②別棟倉庫のペタバイト級映像マスター、約2PB。③そして——DCを完全に閉めるまでの過渡期、現場はオンプレの編集ソフトからファイルを使い続けたい」

矢吹が腕を組んで頷いた。「①と②は、要するに『どうやって運ぶか』だ。③は『運んでる最中もどうやって使い続けるか』だな。前者は引っ越し、後者は引っ越し中の生活だ」

「うまい言い方ですね」美咲は感心した。そして②の付箋を指して軽い気持ちで言った。「②の2PB、回線で送ればいいのでは。専用線もありますし。DataSyncっていう転送サービスもあるって聞きました。夜間に流しておけば」

堂島は何も言わず、美咲に電卓アプリを開かせた。「計算しろ。専用線は何Gbpsだ」

「1Gbpsです」

「2PBを1Gbpsで送る。理論値で何日かかる」

美咲はホワイトボードに式を書いた。2PBはバイトなので、ビットに直すと8倍。`2PB × 8bit ÷ 1Gbps`。ペタをギガに揃えて電卓を叩く。

`2,000,000GB × 8 ÷ 1Gbps ≒ 16,000,000秒 ≒ 185日`

「……百八十五日」美咲の声がしぼんだ。「半年、です」

「それは理論値、回線を100%使い切れたらの話だ」堂島は容赦なかった。「業務トラフィックもTCPのオーバーヘッドもある。実効50%なら倍、一年近くかかる。半年でDCを畳む計画が、②だけで一年溶ける」

美咲は打ちのめされた。前編では帯域の罠で転んだが、今度はそもそも回線で送るという発想自体が誤りだった。

「いいか、判断則をやる」堂島は太字で書いた。「『データ量÷帯域で日数を概算しろ。それが数週間を超えたら、回線じゃなく物理輸送を検討しろ』。送信側の帯域と総量、この二つを掛けるだけで答えはほぼ出る。2PBは、どう転んでも数週間に収まらない。だから②は回線転送を棄却する」

「物理で運ぶやつ、ですね」美咲は前編の最後の台詞を思い出した。

---

「②の物理輸送は**snowball_edge_storage_optimized**だ」堂島が新しい枝を引いた。「AWSが頑丈な物理デバイスを送ってくる。Storage Optimizedモデルは一台で80TB級の使用可能容量がある。データをコピーして送り返せば、AWS側でS3に取り込んでくれる」

「2PBだと、80TBで割って……二十五台?」

「一台ずつ順番に回してたら間に合わん。複数台を並行で発注して、別棟の倉庫で同時にコピーを回す。映像マスターは部署ごとに塊が分かれてるんだろう? デバイスごとに担当を割り振って並列で詰める」

矢吹が確認した。「輸送中のセキュリティはどうなる。三十年の資産が路上で消えたら洒落にならん」

「転送するデータは**KMSで暗号化**される。デバイス自体も耐タンパ設計だ。盗まれても暗号鍵がなければただの箱だ」

美咲はリードタイムを工程表に落とした。発注して到着まで数日、倉庫でのコピーに数日から一週間以上、返送に数日、S3へ取り込まれるまでまた数日。「往復と取り込みで一台あたり二、三週間。並列で回しても、全体で一、二ヶ月ですね」

「それでも一年が二ヶ月になるなら桁違いだ」堂島が頷いた。「物理輸送のリードタイムは、輸送そのものより前後の段取りで決まる。発注→到着→コピー→返送→取り込み。この五工程を必ず工程表に書け」

ここで矢吹が別の付箋を貼った。「ついでに相談だ。地方のロケ先や中継車から回収したい映像がある。一回あたり数TB、せいぜい十数TBだ。これも80TBのデカい箱を毎回送るのか? 中継車に積めんぞ。撮影現場は埃も振動もひどい」

「それは**snowcone**だ」堂島は即答した。「Snowballの小型版で、重さは約2kg、お弁当箱サイズ。容量は8〜14TB級だ。過酷な環境向けで振動や粉塵にも耐える。回収方法は二つ——物理で送り返してもいいし、現場にそこそこの回線があれば**DataSyncエージェント**でオンラインで吸い上げることもできる」

「Snowball Edgeと、どう使い分けるんですか」

「規模だ」堂島は二つを並べて書いた。「数十TB〜PB級のまとまった移行はSnowball Edge Storage Optimized、80TB級を複数台。数TB〜十数TBの小規模回収で過酷な環境や軽さが要るならSnowcone、約2kgで8〜14TB。運ぶ量と現場条件でデバイスを変える」

矢吹がにやりとした。「中継車に80TBの箱は積めんが、お弁当箱なら助手席に置ける。規模で選ぶ、覚えたぞ」

---

「次、①のテープライブラリだ」堂島が地下の奥を指した。「三十年分。これは厄介だぞ」

矢吹の表情が引き締まった。「言っておくが、バックアップソフトと運用手順は変えたくない。三十年、同じソフトでテープに焼いてきた。手順書も、夜勤の連中の身体に染み付いてる。それを全部書き換えろと言うなら、俺は反対する」

「変えなくていい」堂島は言った。「**storage_gateway_tape_gateway**だ。これはオンプレに仮想テープライブラリ——VTLとして見える。バックアップソフトから見たら、今まで通りテープ装置がそこにあるように振る舞う。ソフトも手順も変えなくていい。だが実体は物理テープじゃない。S3だ」

「実体がS3……?」矢吹が眉を寄せた。

「VTLに書いた仮想テープは裏でS3に保存される。アーカイブ指定したテープはGlacierやDeep Archiveへ落とせる。物理テープの保管棚も、オフサイト輸送のトラックも要らない。そして——磁気テープの経年劣化も、もうない。三十年後に読めない、という事故が構造的に消える」

矢吹が黙り込んだ。物理テープの劣化は、彼が長年抱えてきた恐怖そのものだった。

ここで美咲が口を開いた。最初の事件の記憶が蘇っていた。「矢吹さん、一つだけ釘を刺させてください。アーカイブしたテープをGlacier Deep Archiveに落とすと、取り出しには時間がかかります。物理テープを倉庫から探してドライブに掛けるのと、感覚は同じです。すぐ読みたい復元データを、安いからってDeep Archiveに置くのは危険です」

堂島が横目で美咲を見た。「フォトリムでDeep Archiveに本番アルバムを落として青ざめた件、覚えてたか」

「身体で覚えました」美咲は苦笑した。「取り出しの待ち時間は保存単価と引き換え。すぐ要るものは、すぐ出せる階層に」

「いい釘だ」矢吹が低く笑った。「物理テープと同じ感覚なら、むしろ分かりやすい。今の運用も、古いテープは倉庫の奥で、すぐ取り出せやしない」

「Tape Gatewayは、運用を変えずに『物理テープの面倒』だけを消す道具だ」堂島がまとめた。「だから①はこれで決まりだ」

---

「③、過渡期のファイルアクセス」堂島が三つ目に進んだ。「DCを畳むまでの数ヶ月、現場の編集ソフトはオンプレのファイルサーバーを見続けたい。だが中身は順次AWSへ移していく。この『顔はオンプレ、実体はクラウド』を成立させるのが**storage_gateway_file_gateway**——S3 File Gatewayだ」

「どういう仕組みですか」

「オンプレにNFSやSMBの顔を見せる。編集ソフトから見れば、ただのファイルサーバーだ。だが書き込まれたファイルの実体はS3オブジェクトになる。よく使うファイルはゲートウェイのローカルにキャッシュされるから、毎回S3まで取りに行かなくていい。現場は今まで通りNFSマウントを叩くだけで、裏ではS3に載っている」

美咲が引っかかった。「あれ。さっき私、②でDataSyncって言いましたよね。File GatewayもオンプレとS3をつなぐなら……DataSyncと何が違うんですか」

「そこだ」堂島はマーカーを強く置いた。「ここはSAAで最頻出の混同ポイントだ。よく聞け。**継続的なファイルアクセスはFile Gateway。一回限りの移行・同期ジョブはDataSyncだ**」

「継続的か、一回限りか」

「DataSyncは『運ぶ』道具だ。データを大量に高速にコピー・同期し、ジョブが終われば役目も終わる。居座り続けるものじゃない。一方File Gatewayは『使い続ける』道具だ。現場が日々ファイルを読み書きする窓口として、ずっとそこに居る。実体はS3でも、オンプレからはファイルサーバーに見え続ける」

美咲は腑に落ちた。「②の2PBは『一回運んで終わり』だから、本来ならDataSyncの仕事。でも量が多すぎて回線が無理だから、物理のSnowballに化けた。③は『畳むまで毎日使い続ける』から、運ぶDataSyncじゃなくて、居続けるFile Gatewayなんですね」

「その整理だ」堂島が頷いた。「『運ぶジョブ』か『使い続ける窓口』か。これで③はFile Gatewayに決まる」

---

ところが、棚卸しを進めた矢吹が渋い顔で戻ってきた。「厄介なのが出た。旧システムの中に、ファイルじゃなくてiSCSIのブロックストレージを要求するやつが二系統ある。ファイル共有の顔じゃ受け付けん。生のブロックデバイスが要るんだ」

「ブロックなら**storage_gateway_volume_gateway**だ」堂島が言った。「オンプレにiSCSIのブロックボリュームを見せる。二系統あるなら性格を聞かせろ。一つずつ要件を潰す」

「一つ目(a)は撮影素材の一次置き場だ。容量がもう溢れかけてる。だがアクセスは時々で、最近のものしか触らん」

「それは**storage_gateway_volume_gateway_cached**、キャッシュ型だ」堂島が即決した。「主データの本体はS3に置き、ローカルにはよく使うデータだけをキャッシュとして持つ。ローカルのディスク容量に縛られずに、実質的に容量を拡張できる。溢れかけてるなら、これで器が広がる」

「主コピーがS3側にある、と」美咲がメモした。

「二つ目(b)は逆だ」矢吹が続けた。「編集中のプロジェクトファイルで、レイテンシにうるさい。全データを手元に置きたい。クラウドまで取りに行く遅延も許せん。ただ——こいつだけオフサイトのバックアップが一切ない。DCが燃えたら終わりだ」

「それは**storage_gateway_volume_gateway_stored**、保管型だ」堂島が反対側に書いた。「全データの本体はオンプレに置く。ローカルに全部あるからレイテンシは最速だ。そのうえで非同期にAWSへEBSスナップショットとしてバックアップが取られる。普段はローカルで速く使い、万一のときはAWS側のスナップショットから復旧できる。オフサイトバックアップが無いという穴がこれで埋まる」

「キャッシュ型と保管型の違いは」美咲が確認する。

「**主コピーがどっちにあるか、だ**」堂島は二つを線で結んで対比させた。「キャッシュ型は主データがS3、ローカルはキャッシュ——だから容量を拡張できる。保管型は主データがオンプレ、AWSにはスナップショットのバックアップ——だから低レイテンシでオフサイト保全ができる。容量を広げたいか、レイテンシ最優先でバックアップだけ外に欲しいか。要件でどちらか決まる」

矢吹はホワイトボードを見つめ、ふと立ち上がってマーカーを取った。「待て。整理させてくれ」彼は表を書き始めた。「ゲートウェイってのは、全部ひっくるめて**aws_storage_gateway**ってファミリーなんだろう。だったら俺の頭の中はこうだ」

| 形態 | オンプレに見せる顔 | 主な用途 |
|---|---|---|
| File Gateway | NFS/SMB(ファイル) | 実体S3のファイル共有・継続アクセス |
| Tape Gateway | 仮想テープ(VTL) | バックアップソフトそのまま・実体S3/Glacier |
| Volume Gateway キャッシュ型 | iSCSI(ブロック) | 主データS3・ローカルキャッシュで容量拡張 |
| Volume Gateway 保管型 | iSCSI(ブロック) | 主データ手元・AWSへスナップショット退避 |

「四形態だ」矢吹は表を見渡した。「見せる顔がファイルかテープかブロックか。ブロックなら、主コピーがどっちにあるかでキャッシュと保管に割れる。これだけか」

「これだけです」堂島が頷いた。「顔と主コピー、二つ聞けば形態が決まる」

矢吹は表をしばらく眺め、低く唸った。「三十年やってきた道具が、全部この一枚に乗っちまうのか」

---

それから数ヶ月が過ぎた。

最後のSnowball Edgeが返送され、別棟倉庫の映像マスター2PBが最後の一塊までS3に収まった。地方ロケの回収はSnowconeが何往復もして片付けた。地下の奥ではTape Gatewayが旧バックアップソフトの吐く仮想テープを淡々とS3へ流し、夜勤の手順は一行も変わらなかった。過渡期の現場はFile Gatewayの窓口越しに、最後の日まで普段通りファイルを開き続けた。二系統のブロックも、キャッシュ型と保管型に振り分けられ、静かに役目を終えた。

DCを畳む日。空になったラックの列の前に、矢吹が一人で立っていた。三十年、テープを焼き続けたライブラリの電源を、彼は自分の手で落とした。冷却ファンの唸りが止み、地下フロアが初めて静まり返る。

矢吹は誰もいないラックに向かって、深く一礼した。

美咲は少し離れて、その背中を見ていた。声をかけるべきか迷っていると、矢吹が振り返らずに言った。

「クラウドの運用チーム、人が足りんそうだな」

「……はい」

「俺が行く」彼はようやく振り返り、薄く笑った。「箱が無くなっても、データの面倒は誰かが見にゃならん。三十年テープと付き合った俺なら、Glacierの取り出し待ちくらい屁でもない」

クラウド懐疑派だった古参が、自らクラウド側へ合流する。美咲はその選択が、なぜか誇らしかった。

帰り際、堂島のスマホに法務部から着信が入った。短く応対して、彼は妙な顔で電話を切った。

「どうしました」

「移行した三十年分の映像な」堂島は眉を寄せた。「法務が言い出した。——『これは証拠保全の対象だ。誰にも、管理者にも、絶対に消せない保管にしてくれ』とさ」

美咲は固まった。S3に上げた、その先の話だ。消せない保管。

「それは……ライフサイクルで消す話の、真逆ですね」

「真逆だ」堂島は溜息をついた。「畳む話は終わった。今度は、守る話だ」

地下フロアの照明が、ひとつ、またひとつと落ちていった。

## 確認クイズ

1. 専用線1Gbpsで2PBの映像マスターをAWSへ送りたい。回線転送を選ばない理由と判断則は?
   → `2PB×8bit÷1Gbps≒185日`、実効50%なら約1年かかる。「データ量÷帯域で日数を概算し、数週間を超えたら物理輸送」が判断則。本件はSnowball Edge Storage Optimizedを複数台並行で使う。

2. 「オンプレからAWSへの一回限りの大量移行」と「DC閉鎖までオンプレ現場がファイルを使い続ける窓口」。それぞれDataSyncとFile Gatewayのどちらか?
   → 一回限りの移行・同期ジョブはDataSync。継続的なファイルアクセス(NFS/SMBの顔を見せ実体はS3でローカルキャッシュ)はFile Gateway。「運ぶジョブ」か「使い続ける窓口」かで決まる。

3. iSCSIブロックが必要な二系統。(a)容量が溢れかけ、(b)レイテンシ最優先で全データを手元に置きたいがオフサイトバックアップが無い。それぞれVolume Gatewayのどちらか?
   → (a)はキャッシュ型(主データS3+ローカルキャッシュで容量拡張)。(b)は保管型(全データはオンプレで低レイテンシ、非同期でEBSスナップショットをAWSへ)。判別軸は「主コピーがどちらにあるか」。
