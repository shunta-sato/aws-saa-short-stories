# 幕間 流れの中の算盤 — Managed Service for Apache Flink

*SAA-C03 短編小説集 / S5幕間01 — 用語集外の頻出トピック補強(ショートショート)*

---

九月分の請求書は、月初の3日で締まった。跳ねた行は、なかった。

城戸悠介の読み方は決まっている。まず前月比で跳ねた行、次に新しく生えた行、最後に、動かない行を眺めて終わる。跳ねた行は皆が見る。新しい行は、名前を知らないままにしない——それが経理の礼儀だと思っている。

新しい行は、二つあった。一つは急上昇の係に配った専用車線の追加料金で、これは自分で釘を刺して通した口だから顔を知っている。もう一つの行は、名前が長かった。Managed Service for Apache Flink。読み方から、自信がない。

金曜の午後、川まわりの月次確認に来た青柳凛を、城戸は自分の隣の椅子に座らせた。真鍋一花は湖の棚の設計にかかりきりで、川の帳尻はこのところ青柳の持ち場になっている。経理の小会議室は南向きで、電卓の液晶に十月の西日が入っていた。

「で——」城戸はその一行を、ボールペンの尻で指した。「この行、何しとるんです?」

「急上昇の、集計係です」

「係がおるんは知ってます。土曜に一遍サボった係でしょう」皮肉ではなく、帳簿の記憶として言った。「私が聞きたいんは中身です。この行だけ、夜中の3時も同じ顔で動いとる。時間で課金される行ですわ。何をそんなに、夜通しやることがあるんです」

青柳はノートPCを開き、見慣れた構成図を出した。川があり、読み手が三人並んでいる。湖行き、検証、急上昇。今日の議題は、その急上昇の箱の中身だった。

「5分ごとに、どこぞの表へ全部入れて、数え直しとるんと違うんですか」城戸は言った。「ほんで上位を出す。私が組むなら、そうします」

「それ、ぼくが最初に出した案です」青柳は言った。「真鍋さんに一枚で却下されました」

却下の紙は今も残っている。5分ごとに表へ着地させて数え直す案は、行事の朝には書きが表を叩き倒すし、数え直しのたびに同じ記録を何度も読む。夏に器で払った授業料と、同じ形の請求がもう一度来る——そう書いてあった。

「じゃあ、どこで数えとるんです」

「川の中です」

青柳は構成図の急上昇の箱を開いた。中に立っているのがFlinkの係である。川から流れてくる「見た」「タグを付けた」という出来事を、5分の窓で区切る。窓の中で、学校ごと、写真ごとに数える。窓が締まったら、上位だけを吐き出して、窓は捨てる。素の記録は係の手元に残らない——残す仕事は、湖行きの配送屋が別でやっている。着地せずに、流れたまま数える。

城戸はしばらく図を見ていた。それから、自分の言葉に訳した。

「……伝票を、綴じる前に数えとるんですか」

「綴じるのは湖の係です。この係は、窓口を通る伝票を、通るそばから数えてるだけです」

「遅れて届く伝票は、どうするんです」

即座に来た。さすがに急所を突く、と青柳は思った。月末に締めたあと、営業が領収書をポケットから出してくる。どこの帳簿にもある話だ。

「待ちます。窓を締めてから、遅刻をどれだけ待つかの猶予が決めてあります。うちは60秒です。それより遅れた分は、5分の速報には入りません。湖には入るので、確定の集計では数えます」

城戸は電卓を、音を立てずに置いた。

「——青柳さん。私はね、商業高校の簿記の授業から数えて20年、締めた数字で飯を食うてきました。月末に締めて、翌月5営業日で役員に出す。締めるいうんは、この数字はもう動きません、いう約束です。動く数字は、まだ数字やない。……窓が締まるたび吐き出されるやつは、締めとるように見えて、遅刻を60秒しか待たん仮の締めでしょう。そういう数字を、私は信じてええんですか」

意地悪で言っているのではなかった。この人は疑うのが仕事で、疑い方に筋が通っている。青柳は答えを急がず、一度だけ画面から手を離した。

「信じ方が、二つあるんだと思います」と青柳は言った。「Flinkの数字は速報です。速く出る代わりに、遅刻を待ちません。締めた数字は、夜のバッチが湖から作ります。遅い代わりに、全部入っています。速報と確定を別の帳簿にして、両方持てばいいんです。速報で動いて、確定で答え合わせをする。ずれていたら、ずれた分が遅刻の量です」

城戸は答えなかった。湯呑みを取り、一口だけ飲んで、戻した。窓の外を、港の方へカラスが二羽渡っていった。

「……選挙の晩と一緒ですな」やがて城戸は言った。「開票速報で当確を打って、確定は明け方に出る。誰も速報を嘘やとは言いません。打ち方の作法が決まっとるからです」

「はい。その作法が、窓の幅と、遅刻の猶予です」

「速報と確定がずれとったら、どっちが正しい、いうことになります」

「確定です。いつでも確定です」青柳は言い切った。「速報は、確定が出るまでの間、判断を止めないための数字です」

城戸は頷き、請求書に戻った。まだ一つ、腑に落ちていない行がある。

「ほんで、夜中の分です。夜中の3時に、急上昇もへったくれもないでしょう」

「夜は、暇です」青柳は正直に言った。「でも係を夜だけ帰らせて、朝また呼ぶと、呼び戻す手間と、係が窓の途中から立て直すまで速報が消える時間が出ます。それで、立たせたままにしてます。人と違って、立たせておく分は時間いくらで読めますから」

城戸の指が電卓の上で動いた。係の背丈は3KPU。それが24時間、31日。指は二往復して止まり、乾いた声が出た。

「窓口を終夜開けとく家賃や思えば、読める値段です。読めるんが、ええことですわ」

そう言って、請求書のその行の余白に、細い字で摘要を書き入れた。急上昇の窓口(終夜)。名前の分からん行を役員に出すわけにはいきませんのでな、と手を動かしながら言う。ボールペンの先が、長い横文字の上に短い日本語の橋を架けた。

帰り際、給湯室の前で城戸が茶を淹れ直してくれた。薄かった。

「経理の茶が薄いんは、濃いと数字が跳ねて見えるからです」

「本当ですか」

「嘘です。単に、補充を忘れるだけです」

---

翌月の月次資料——役員向けの一枚目の隅に、小さな欄が一つ増えた。**速報(参考値)**。確定の数字の隣で、半角ぶんだけ遠慮して立っている。配られた資料に目を留めた堂島美咲が訊くと、城戸は湯呑みを持ったまま言った。

「算盤に、川の水が一滴入りました」

コスト承認の綴りには、青柳の名前で一件、判が並んだ。実装した者の欄も、説明した者の欄も、同じ名前である。それを誰かが話題にすることは、なかった。

廊下の窓から、暮れかけの港が見えた。汽笛が一つ鳴って、消えた。

## 補講コラム — Amazon Managed Service for Apache Flink(旧Kinesis Data Analytics)

**ストリーミングデータを「流れたまま」リアルタイムに集計・分析するマネージドFlink基盤。タンブリング/スライディングウィンドウでの集計・結合・ストリームETLが要件語。** Kinesis Data StreamsやMSKを入力に、時間の窓で区切った集計を継続的に実行し、結果をストリームや宛先へ書き出す。旧称はAmazon Kinesis Data Analyticsで、試験ではこの名前でも出題される(SQLベースの旧方式は廃止方向で、現行はFlinkアプリケーション)。課金はKPU(1KPU=1vCPU+4GBメモリ)単位の時間課金で、アプリケーションが動いている間は流量が薄くても課金が続く——「窓口を終夜開けておく家賃」である。

試験での決め手: 「ストリーミングデータをリアルタイムに集計・変換したい」「5分ごとの集計値を継続的に出したい」ならFlink側が正答。定番のひっかけは2つ——「Firehoseで集計する」(誤: Firehoseは配送と軽い変換のみで、集計はしない)、「Athenaでリアルタイム集計する」(誤: AthenaはS3に着地した後のデータへの対話クエリで、着地とバッファの分だけ必ず遅れる)。着地後のバッチETLならGlue/EMR、流れの中の窓集計ならFlink——データが着地する前か後か、で切り分ける。

## 確認クイズ

1. クリックストリームをKinesis Data Streamsで受けている。(a)「5分ごとの急上昇ランキングをリアルタイムに出す」(b)「全イベントをS3に蓄積する」(c)「蓄積したデータを翌日SQLで分析する」——それぞれに使うサービスは?
   → (a)Amazon Managed Service for Apache Flink(旧Kinesis Data Analytics)。タンブリングウィンドウで流れたまま集計する。Firehose(配送のみ)やAthena(着地後の対話クエリ)では要件を満たせない。(b)Amazon Data Firehose——コンシューマを自作せず配送はマネージドに任せる。(c)Amazon Athena。リアルタイムの窓集計=Flink、配送=Firehose、着地後の対話分析=Athena、と役割の動詞で覚える。
