# 短編5: 消せないデータ、消えないデータ — S3保護編

*SAA-C03 短編小説集 / storage_architecture (5/5)*

---

その悲鳴は、午後三時の運用部屋に響いた。

「やってしまいました——本番の、メタデータを、消しました」

声の主は今月配属された新人の青柳だった。画面には実行済みの`aws s3 rm`が残っている。ステージング用バケットを掃除するつもりが、プロファイルを取り違え、本番の`photorim-media-meta`に走らせてしまった。映像一本ごとに紐づくメタデータJSON——撮影日、権利者、解像度、サムネイル参照。それが数百件、コマンド一発で消えていた。

青柳の顔は紙のように白い。隣で矢吹が腕を組み、低く唸った。東雲アーカイブズ社の買収でクラウド運用チームに合流した古参だ。「テープなら……いや、これはクラウドか」

ところが瀬名美咲は、椅子から立ち上がりもしなかった。マグカップを置き、静かにこう言った。

「青柳くん、深呼吸して。そのバケット、消えてない」

「でも、削除コマンドが通って——」

「**Amazon S3**のそのバケットは、**S3バージョニング**を有効にしてある。バージョニングが有効なバケットでは、削除しても物体は消えない。**削除マーカー**という新しいバージョンが一番上に乗るだけ」

美咲はコンソールを開き、バージョン表示をオンにした。すると消えたはずのJSONたちが、ずらりと姿を現す。それぞれの最新バージョンに「削除マーカー」が被さっているだけで、その下に旧バージョンが温存されている。

「上書きしても、削除しても、バージョニングは『世代』として残す。今回は削除マーカーを外せば、その下の本物が最新に戻る」

美咲は対象プレフィックスの削除マーカーを一括除去した。数十秒後、メタデータは何事もなかったように復活した。青柳が崩れ落ちるように礼を言う。

通りかかった堂島が、画面を一瞥して言った。「助かったな。ただ勘違いするなよ、青柳。**Amazon S3**は11ナイン——99.999999999%の耐久性でデータを失わない。だがそれは『S3側の故障で消えない』という話だ。**お前の誤操作からは、耐久性は守ってくれない**。ディスクが何重に冗長でも、人間が`rm`と打てば消える。耐久性と保護は、別物だ」

その「別物」を、フォトリムはこの日から本気で設計し直すことになる。

---

翌週、会議室に法務部の狩野が現れた。眼鏡の奥の目が、要件定義書を一行ずつ睨んでいる。理詰めの人だと、美咲は最初の一言で悟った。

「技術の話は分かりません。私が知りたいのは、契約と訴訟に耐えるかどうかです。三つ、要件があります」

狩野は指を立てた。

「一つ。放送局から預かる契約映像。これは**契約期間七年、何人たりとも削除・改変できてはならない**。私でも、社長でも、システム管理者でも、AWSのルートユーザーとやらでも。一文字も変えられない状態を、七年間。」

「二つ。社内の通常アーカイブ。**原則として削除は禁止**したい。ただし正当な業務上の理由があれば、権限を持つ管理者が例外的に消せる。そして**その例外操作の記録は残したい**。」

「三つ。いま進行中の訴訟に関わるデータ。これは**いつまで保全すべきか、まだ分からない**。裁判が終わるまで——期限は未定のまま、削除を止めてほしい。」

美咲はホワイトボードにペンを走らせた。「全部、**S3 Object Lock**で答えられます」

「オブジェクト……ロック」

「WORM——Write Once Read Many、一度書いたら読むだけ、を実現する仕組みです。重要な前提が二つ。**Object Lockはバージョニングが前提で、しかもバケットを作るときに有効化しないといけない**。後から既存のバケットに付けることは、原則できません。だから新しい保護バケットを切ります」

そして三本の線を引いた。

**要件①——コンプライアンスモード。**

「契約映像は**S3 Object Lockのコンプライアンスモード**で、保持期間を七年に設定します。このモードでは、保持期間が切れるまで**ルートユーザーですらオブジェクトを削除できない、保持期間を短縮することもできない**。完全なWORMです」

狩野が頷きかけて、美咲が一拍置いた。

「ただし、ここが怖いところです。**コンプライアンスモードは、設定ミスも直せない**。七年と入れるべきところを七十年と打ち込んでも、誰も短くできない。期間を間違えたら、その間違いごと凍結される。だから設定値は二重三重に確認してから入れます」

「……つまり、強い鍵ほど、掛け間違えると開かない、と」

「その通りです」

**要件②——ガバナンスモード。**

「社内アーカイブは**S3 Object Lockのガバナンスモード**にします。原則は削除禁止。ただし`s3:BypassGovernanceRetention`という特別な権限を持つ管理者だけが、例外的に保持を解除して操作できる。普通の運用者は消せないけれど、正当な理由のある管理者は——明示的にバイパスを宣言したうえで——消せる。そして誰がいつバイパスしたかはCloudTrailに残る。『原則禁止、でも例外は残したい』に、ぴったりです」

**要件③——リーガルホールド。**

「訴訟データは期限が決まっていない。だから保持期間では対処できません。ここで使うのが**S3 リーガルホールド**です。これは保持期間とは完全に独立した、無期限のロック。日数を指定しません。**権限を持つ人が明示的に解除するまで、削除できない**。裁判が終わって法務が『もう解いていい』と判断した瞬間に外せばいい」

狩野は要件定義書に何か書き込み、ゆっくり顔を上げて復唱した。

「整理させてください。**期間が決まっているもの**はリテンション——保持期間で縛る。**期限が未定のもの**はリーガルホールド。そして同じリテンションでも、**誰一人として解除できないものはコンプライアンスモード、例外を残したいものはガバナンスモード**。……合っていますか」

「完璧です」と美咲。狩野が初めて、わずかに口角を上げた。

矢吹が手を挙げた。「俺がオンプレで使ってたテープには、物理的に書き込み禁止のツメがあった。あれに近い話だな。ところで、もっと根本的に『バージョンごと完全に消す』のを止める手はないのか」

「**S3 MFA Delete**ですね」と美咲。「バージョンの完全削除や、バージョニング自体の停止に、MFA——多要素認証のコードを必須にする仕組みです。ただし制約が重い。**有効化できるのはバケット所有者のルートユーザーだけ、しかもCLIからしか設定できない**。日常運用のたびにルートのMFAを叩くのは現実的じゃない。だから今回は主役にしません。Object Lockで守りの本体を組んで、MFA Deleteは最重要バケットに限定して補助的に使います」

「主役はObject Lock、MFA Deleteは脇役」堂島が壁にもたれたまま言った。「運用の重さも要件のうちだ。守りが重すぎて誰も動かさなくなったら、それは穴と同じだ」

---

設計はセキュリティレビューに回り、そこで鋭い指摘が刺さった。

「同一アカウント内でObject Lockを掛けても、**アカウントそのものが侵害されたら**? 攻撃者が権限を奪えば、ガバナンスモードはバイパスされうるし、ログも改竄されかねない。保護と、保護を見張るログが、同じ籠の中にある」

美咲は唸った。確かにそうだ。卵を一つの籠に盛っている。

「籠を分けます。別アカウントに隔離バケットを用意して、**S3 同一リージョンレプリケーション(SRR)**で複製を流します。同一リージョン内で、しかし**別アカウント**へ。ログ集約と削除権限を本番から物理的に切り離す。運用者は本番を触れても、隔離側のコピーには手が届かない」

「制約は」と矢吹。

「**SRRもバージョニングが前提**。それと、**レプリケーションは設定後に作られたオブジェクトが対象で、既存のオブジェクトは既定では複製されない**。過去分を含めたいなら、バッチレプリケーションを別途回す必要があります。ここを忘れると『昔のデータが隔離側に無い』という穴になる」

「リージョンごと飛んだら?」と狩野。

「それは災害対策の話ですね。**S3 クロスリージョンレプリケーション(CRR)**を使って、東京から大阪リージョンへもう一本複製します。リージョン全体が落ちても、大阪に映像資産が残る」

狩野が要件定義書をめくり、また理詰めの問いを放った。

「複製は、いつまでに終わるんですか。『複製している』では監査に書けない。『何分以内に複製が完了することを、誰が保証するのか』を書きたい」

美咲は一瞬詰まり、それから答えを思い出した。

「通常のレプリケーションは**ベストエフォート**です。たいてい数分ですが、混めば遅れることもあり、SLAはありません。監査に書ける保証が要るなら、**S3 Replication Time Control(RTC)**を有効にします。RTCは**99.99%のオブジェクトを15分以内に複製することをSLAで保証**し、複製の遅延メトリクスも出る。追加料金はかかりますが、『十五分以内、四桁の九で保証』と監査報告書に明記できます」

「ベストエフォートか、SLAか」狩野は復唱した。「契約映像はSLAの方でお願いします。十五分。書けます」

---

守りが固まると、今度は日常業務から軽い悲鳴が上がってきた。幕間のような相談が二つ。

分析チームの担当者がぼやいた。「数GBのCSVから特定の地域の行だけ欲しいのに、毎回ファイルを丸ごと落として手元で絞ってる。転送量も時間も無駄で」

「単一のオブジェクトから条件に合う行だけ抜くなら、**S3 Select**です」と美咲。「S3にSQLを投げて、中身をサーバー側でフィルタしてから返してもらえる。丸ごと落とさず必要な行だけ。転送量がぐっと減ります」

「複数ファイルを横断して集計したいときは?」

「それはS3 Selectの守備範囲外。**複数オブジェクトをまたぐクエリはAthenaの領域**です。Selectは『一つのオブジェクトの中を絞る』ためのもの。一個か複数か、で道具が変わります」

もう一つは動画チームから。「数十GBの映像ファイルの、先頭のメタデータ部分だけ読みたいんです。全部落とすと時間がかかって。あと、大きいファイルを並列で速く落とす手も知りたい」

「**バイトレンジフェッチ**ですね」美咲はそう言って、ふと第1編を思い出した。「リクエストに`Range`ヘッダーを付けて、オブジェクトの一部分だけ取得する。先頭の数百KBだけ読めばメタデータが取れます。さらに範囲ごとに分けて複数リクエストを並列で投げれば、ダウンロードも速くなる」

矢吹が口を挟んだ。「アップロードのときに分割してたやつの、逆か」

「ええ。アップロード側の**マルチパートアップロード**と、ダウンロード側のバイトレンジフェッチは、対の関係です。上げるときも下ろすときも、巨大ファイルは分けて並列にする。第1編で動画アップロードをマルチパートにしたのと、考え方は同じ鏡像です」

---

そして最後の仕上げ。東雲アーカイブズ社から引き継いだ三十年分の映像を、どの**ストレージクラス**に置くか。美咲は矢吹を呼んだ。資産の素性を一番知っているのは、この古参だ。

二人は素材を取り出し要件——「取り出しにどれだけ待てるか」——で仕分けていった。

「四半期に数回は、即座に再生したい名作素材。CMや特番で急に引っ張られる」と矢吹。

「それは**S3 Glacier Instant Retrieval**です」と美咲。「アーカイブ料金で安く置けるのに、**取り出しはミリ秒**。Standard-IAより保存が安く、即時取り出しが効く。最小保管期間は90日。四半期に一度触る素材なら90日は楽に超えます」

「年に一度触るかどうか、でも『いざというとき選べる速さ』は確保したい古い番組群は」

「**S3 Glacier Flexible Retrieval**。取り出しの速度を選べます。**迅速(Expedited)なら1〜5分、標準なら3〜5時間、バルクなら5〜12時間**。緊急なら速く、急がないなら安く。柔軟さが名前の通りです」

「で、契約上は持つ義務があるが、まず誰も触らない死蔵データ」

美咲の手が止まった。第1編の、あの十二時間が頭をよぎる。間違えて本番アルバムをDeep Archiveに落とし、最短でも十二時間待つしかなかった日。

「死蔵データは**S3 Glacier Deep Archive**。最安です。でも矢吹さん——」美咲は強い声で言った。「**即時が要るかもしれないものは、絶対にDeepに入れない**。Deepは迅速取り出しが無くて標準で十二時間。一度それで痛い目を見ました。『たぶん使わない』と『絶対使わない』は違う。少しでも使う芽があるなら、InstantかFlexibleに置きます」

矢吹は深く頷いた。「テープを倉庫の奥に入れるか、手前に置くか、だな。出庫にかかる時間で棚を決める。同じだ」

「結局、**Amazon S3 Glacier**ファミリーは——」美咲は対応表の一番下に書いた。「**取り出しのSLAから逆算して選ぶ**。ミリ秒ならInstant、分〜時間で柔軟ならFlexible、半日待てるならDeep。要件の『待てる時間』が階層を決める」

---

すべての設計をまとめ、美咲は狩野に最終報告書を渡した。狩野はそれを読み終え、眼鏡を外して言った。

「分かりました。私はずっと『データが消えないこと』を求めているつもりでした。でも本当に欲しかったのは、別のことだったんですね。——**データが消えないことと、消せないことは、違う**」

「11ナインの耐久性は『勝手には消えない』を保証する。でも『誰にも消させない』は、バージョニングとObject Lockで自分で作るものです」と美咲は微笑んだ。

報告書の結びに、美咲はこう書いた。

> 耐久性はAWSが守る。保護はわたしたちが設計する。消えないことと消せないことを取り違えた瞬間、データは守られているように見えて、いつでも消せる。

堂島が報告書を覗き込み、満足げに頷いてから、全員に向き直った。

「ストレージの守りは固まった。バージョニング、Object Lock、レプリケーション、階層——データの城壁は組み上がった。だが城壁が無事でも、城が落ちることはある」堂島は壁のカレンダーを指した。「次は会社全体だ。**金曜にゲームデーをやる**。リージョンが丸ごと落ちた前提で、本番を止めて障害訓練する。システム全体が何分で立ち直れるか——RPOとRTOを、机上じゃなく身体で測る」

青柳が、まだ少し青い顔で訊いた。「本番を、止めるんですか」

「壊して学べ。安全に壊せるうちにな」堂島はにやりと笑った。「金曜、空けとけ」

## 確認クイズ

1. 「保持期間中はルートユーザーでも削除・期間短縮ができない」モードは? また設定上の最大の注意点は?
   → S3 Object Lockのコンプライアンスモード。期間の設定ミスも誰も直せず凍結されるため、設定値は事前に二重三重に確認する。

2. 「いつまで保全するか期限が未定」のデータを削除禁止にしたい。保持期間とリーガルホールドのどちらを使うか? 理由は?
   → リーガルホールド。保持期間は日数指定が前提だが、リーガルホールドは期間と独立した無期限のロックで、権限者が明示解除するまで有効だから。

3. 通常のレプリケーションと、監査に「15分以内・99.99%」と書ける構成の違いは?
   → 通常はベストエフォートでSLAなし。S3 Replication Time Control(RTC)を有効にすると99.99%を15分以内に複製するSLAと遅延メトリクスが付く(追加料金あり)。
